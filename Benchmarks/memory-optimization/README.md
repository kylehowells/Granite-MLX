# Long-input memory optimization

The original 34.67 GB macOS peak was not the raw waveform. The 6,118.72-second
mono Float32 waveform occupies about 392 MB, and the FP16 frontend feature
tensor about 196 MB. The two dominant sources were:

1. Long-sequence intermediate tensors. Before the first two subsampling layers,
   a 4,096-channel feed-forward/convolution expansion is about 2.51 GB. After
   subsampling, each 16,384-vocabulary CTC logits tensor is about 2.51 GB in
   FP16, and each FP32 softmax-sized tensor is about 5.01 GB. Several inputs,
   outputs, casts, reductions, and residuals coexist during a kernel sequence.
2. MLX's default recycled-buffer cache. On this 64 GB Mac its limit was about
   65.3 GB, so buffers released by one operation remained allocated for reuse.
   At the end of the unbounded run MLX reported 33.35 GB cached even though only
   489 MB remained active.

Disabling the cache reduced system peak from 34.67 GB to 12.64 GB. Exact tiled
middle CTC softmax/projection reduced that to 9.66 GB. The remaining one-pass
peak comes from the early full-temporal-resolution Conformer layers, so audio
file compression or incremental WAV decoding alone cannot solve it.

## Results

All results use the same 101m59s mono 16 kHz lecture and mixed-G128 Q8 weights
unless specified otherwise.

| Profile | Inference | Peak footprint | Disagreement vs same-weight one pass |
|---|---:|---:|---:|
| One pass, default MLX cache | 17.86 s | 34.67 GB | 0% |
| One pass, cache disabled | 20.55 s | 12.64 GB | 0% |
| One pass, cache disabled, middle tile 2048 | 22.57 s | 9.66 GB | 0% |
| 122.88s cores, no context, cache disabled | 18.06 s | 1.51 GB | 1.197% |
| 122.88s cores, 20.48s context, 64 MiB cache | 24.41 s | 1.64 GB | 0.169% |

The recommended bounded-memory Q8 profile processes block-aligned 122.88-second
cores with 20.48 seconds of context on both sides. Only central frame emissions
are retained; CTC collapse and BPE decoding happen once over the complete frame
sequence. It remains 250.7x real time on the M1 Max.

Q6 lowers this profile to 1.50 GB and has 0.140% disagreement against its own
one-pass output. Q5 reaches 1.44 GB and 0.198%, but its weight quantization is
already less faithful to FP32. Q6 is the better secondary mobile preset.

Context-window output is not byte-identical to one-pass because frontend and
convolution boundary conditions differ. Exact mobile streaming would require
layer-wise temporal tiling: block-aligned attention tiles, convolution halos,
and tiled pointwise/feed-forward operations through the first high-resolution
layers. That is the next route below the approximate 1.4--1.6 GB process floor.

The current CLI still loads the complete decoded Float32 waveform before
forming model chunks. An isolated 163.84-second maximum-size model window
peaked at 1.22 GB, 422 MB below the full-file bounded Q8 run. This indicates a
streaming AVFoundation/ffmpeg loader should bring Q8 file transcription close
to 1.22 GB and Q6 close to roughly 1.1 GB on this Mac. This is a projection from
a measured maximum-window run, not yet a completed streaming full-file result;
physical iPhone/iPad validation remains required because iOS jetsam limits and
Metal allocation behavior differ from macOS.

`results.json` preserves every measured configuration and transcript-relative
diagnostic. PNG charts are generated by `Scripts/chart_memory_optimization.py`.
